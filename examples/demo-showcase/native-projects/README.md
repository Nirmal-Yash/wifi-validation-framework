# Native topology fixtures

These files are import fixtures for Topology Studio. They preserve supported network objects and placement in NetRegress' canonical, provider-independent topology revision. They are not complete virtual-machine projects.

| File | Format | Approximate content | Import adapter |
|---|---|---|---|
| NetRegress-Branch-Office.gns3 | GNS3 project JSON 2.2 / revision 9 | 4 nodes, 3 links | GNS3 |
| NetRegress-CML-Campus.yaml | Cisco CML Lab YAML 0.1.0 | 3 nodes, 2 links, supported annotations | CML |
| NetRegress-EVE-NG-Branch.unl | EVE-NG lab XML v1 | 3 devices and 2 shared bridge networks | EVE-NG |
| NetRegress-Packet-Tracer-Branch.pkt | Cisco Packet Tracer binary | generated locally by the pinned pktlib codec | Packet Tracer |

## Import from the UI

1. Open Topology Studio and select the target Project.
2. Use the first-run native import form, or the native project import panel when a profile is already selected.
3. Choose a profile name and Project or Lab scope.
4. Select one of the files above and import.
5. Inspect node placement, link endpoints, interface names, codec compatibility report and immutable native-source provenance.
6. Run canonical validation and save a DRAFT revision. Publish it only when you intend to retain that design.

The first-run import form creates its own profile and draft. You do not need to create an empty profile first.

## Format boundaries

- GNS3 support is limited to the project revisions/versions implemented by the registered codec. This fixture targets GNS3 2.2. Its source references do not include the referenced VM images, compute hosts, startup configs or controller session.
- CML support targets the implemented Lab YAML 0.1.x schema. This fixture targets 0.1.0. Reopening the file in VM Maestro is a separate acceptance check.
- EVE-NG support targets UNL versions 1 and 2. The codec represents shared bridge networks as logical links. EVE Community/Professional controller execution and images are separate.
- Packet Tracer uses the repository's pinned pktlib parser and constrained serializer. The generator verifies codec decoding and canonical conversion only. It does not establish that a licensed Packet Tracer desktop can reopen the generated file.

To create the Packet Tracer fixture:

```bash
source wifi-venv/bin/activate
python scripts/generate_demo_packet_tracer.py
```

The helper refuses to overwrite an existing file unless --force is explicitly supplied. It prints the output's byte length, SHA-256 and parsed node/link counts.

## What these fixtures do not prove

Import success proves file parsing and canonical conversion only. It does not mean that a provider is configured, that templates/images exist, that devices are running, or that any emulator has been launched. Provider binding and live controller operations require their own explicit, approved configuration and observations. No Runs, device-health records, captures, metrics, deployment results or regression evidence are generated by these fixtures.
